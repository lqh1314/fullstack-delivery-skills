# 08 · 质量门：测试 · 评审 · 安全 · 性能 · 可观测 · 发布

> 对应主线 A 的 A4/A5 与一切"写完之后"的把关。三路（测试/安全/性能）并行、互不替代；Critical/High 不清零不交付。

## 1. TDD 纪律（复杂逻辑优先）
红（写一个失败测试表达需求）→ 绿（写最小实现让它过）→ 重构（在测试保护下改善结构）。禁止"先写一堆实现最后补测试"——补的测试倾向复述实现而非验证行为。
- 每个功能三类用例：**正常路径 / 边界条件 / 错误处理**；bug 先复现为失败测试再修，该测试永久保留。
- 测试要验证行为不验证实现细节；不要 mock 掉一切导致测试不验证真实协作；不为覆盖率写无断言测试。
- 金字塔：大量快单元、适量切片/集成、少量端到端（Java 70/20/10 见 04 §5）；新代码覆盖 80%+，断言质量优先于数字。
- 先发现项目自己的测试命令与栈，不新引框架（Python pytest、Java JUnit5+AssertJ+Testcontainers、JS Vitest/Jest+Testing Library+Playwright）。

## 2. 代码评审五轴（自审/评审都按此走，单次变更尽量控制在约 100 行内更易审）
1. **正确性**：边界、空值、并发、错误路径是否成立；逻辑是否真的解决问题而非表面通过。
2. **安全**：见 §3。
3. **可维护性**：职责单一、命名达意、无重复、无上帝类/超长函数；复杂处有注释说"为什么"。
4. **性能**：见 §4，是否有明显 N+1/全量加载/无界列表/重复渲染。
5. **可测试性/一致性**：是否易测、是否遵循项目既有模式（Chesterton 围栏：不理解为何这样写之前不随意删除既有逻辑；Rule of 500：单文件/函数超规模就拆）。
- 评审给结论时标注级别与具体位置、修法；只提"建议重构"不给依据属于无效评审。本地可复用 `code-review-excellence`、`doubao-coding-review-code`、`receiving/requesting-code-review`。

## 3. 安全清单（OWASP，逐条给位置+严重度+修法）
- [ ] **越权**：未登录/低权能否访问；水平越权（A 操作 B 的资源，必须比对归属）、垂直越权
- [ ] **注入**：SQL/NoSQL/命令/模板/LDAP 注入——参数化、ORM 绑定，绝不字符串拼 SQL
- [ ] **XSS/CSRF**：输入转义、输出编码、CSP；Cookie 会话的 CSRF token/SameSite
- [ ] **输入校验**：类型/长度/范围/白名单、上传类型与大小、schema 校验在边界
- [ ] **认证与会话**：密码哈希（bcrypt/Argon2）、令牌短过期+刷新分离、安全 Cookie、登录限流
- [ ] **敏感数据**：日志/响应/报错/前端包不泄露密钥、堆栈、个人信息；传输加密
- [ ] **依赖与配置**：已知 CVE 扫描、默认口令、调试接口关闭、CORS 白名单、安全响应头
- [ ] **加密**：不用 MD5/SHA1 做安全用途、不用弱随机数生成令牌、不自造加密算法
- 严重度：Critical（可直接利用/数据损坏/主流程不可用）立即修；High（越权/严重缺陷）本阶段修；Medium 与用户确认；Low 入 backlog。

## 4. 性能清单（先测量再优化，优化后复测对比）
- 数据：N+1/循环查库、缺索引/全表扫描、深分页、无界列表、大 payload、缺缓存的热点读
- 后端：不必要的同步阻塞、线程池/连接池大小、锁竞争、重复计算、同步外部调用无超时
- 前端：不必要重渲染、缺 memo/虚拟列表、大依赖进主包、未懒加载、未压缩资源
- JVM/Python/Node 专项分别见 04 §12、05、06；每条发现给影响估计与具体修法，不做无证据的"感觉优化"。

## 5. 可观测性（上线前就要有）
- **日志**：结构化、分级、带请求/traceId 与关键上下文，不记敏感信息；错误日志足以定位问题。
- **指标 RED**：每接口/服务 Rate（请求量）、Errors（错误率）、Duration（延迟分位 P50/P95/P99）；业务关键指标另设。
- **追踪**：分布式调用链 traceId 贯穿（微服务/异步任务也要传递）。
- **健康**：liveness（进程活着）与 readiness（能接流量，依赖就绪）分离；告警设阈值与降噪。
- Java 用 Actuator + Micrometer/Tracing，Python 用对应 metrics/tracing 库，Node 同类；本地读各语言 observability 技能。

## 6. 发布检查单（DoD 的落地版）
- [ ] CI 质量门：依赖安装→lint/类型检查→测试→构建全过才允许部署；测试不过禁止发布
- [ ] 数据库迁移作为独立阶段：先迁移（向后兼容、可回滚）后发布应用；回滚顺序写进 runbook
- [ ] 灰度/特性开关：复杂功能可不发版关闭；发布后有验证手段与回滚路径
- [ ] 健康探针、核心指标与告警就位；密钥与环境变量在目标环境配置好
- [ ] 完成前真实验证（不用"应该可以"替代）：干净环境装依赖→构建→全量测试→迁移正反演练→真实启动按验收标准走主流程→Critical/High 清零→清调试残留
- [ ] 交接：接口文档、变更说明、ADR、做了什么/怎么验/已知限制/backlog
- [ ] Git 卫生：小步提交、信息清晰、主干开发或特性分支合并前评审、无密钥/大文件入库
