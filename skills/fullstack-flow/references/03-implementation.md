# Phase 3：分层实现（产出 04、05、06 摘要）

> 顺序不可调换：DB 层 → 后端 → 前端。每层开工前读需求与设计文件，以及上一层的实现摘要；不依赖上下文记忆。

## 通用纪律（三层都适用）

- **先读后写**：先找到项目中最相似的现有实现，沿用其框架用法、目录结构、命名、错误处理与日志风格；不要引入未经同意的新依赖或新范式。
- **小步可验证**：每完成一个可运行单元就做最小验证（导入不报错、单测能跑、页面能渲染），不要攒到最后一起调。
- **改动留痕**：每层结束写实现摘要：新建/修改了哪些文件、关键决策、遗留问题。
- 报错立即按根因调试处理，不带病推进。

## Step 1：数据库层（04-db-impl.md）

- [ ] 按 02 设计编写迁移脚本（正向 + 回滚）；
- [ ] 实现模型/实体，字段与约束和设计一致；

## Step 2：后端服务（05-backend-impl.md）

开工前读：01-requirements、03-architecture、04-db-impl。

- [ ] 按架构实现接口/resolver，请求/响应与错误码和设计一致；
- [ ] 业务逻辑落在服务层，控制器只做协议转换；
- [ ] 接通数据访问层，事务边界清晰；
- [ ] 输入校验（边界、类型、长度、权限）在入口统一完成；
- [ ] 鉴权/授权中间件按设计接入；
- [ ] 关键路径加结构化日志（不记录敏感信息）；
- [ ] 手动/脚本验证每个接口的成功与失败响应。

## Step 3：前端界面（06-frontend-impl.md）

开工前读：01-requirements、03-architecture、05-backend-impl。纯后端功能跳过本步并在文件中说明原因。

- [ ] 按组件层级实现页面/容器/展示组件；
- [ ] 实现状态管理与数据流，服务端状态与本地状态分开；
- [ ] 按取数策略对接后端，处理 loading / empty / error 三态；
- [ ] 表单：前端校验、提交态、防重复提交、后端错误回显；
- [ ] 需要处使用乐观更新，并处理回滚；
- [ ] 响应式布局与基础可访问性（语义化标签、ARIA、键盘可达）；
- [ ] 真实跑通主路径，而不是只看静态渲染。
