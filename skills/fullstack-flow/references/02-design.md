## 1. 数据库与数据模型设计（02-database-design.md）

以数据架构师视角交付六项，缺一项不进入下一步：

1. **实体关系**：表/集合、关系、基数（1:1 / 1:N / N:N），附 ER 关系文字描述；
2. **Schema 定义**：字段类型、约束、默认值、可空性、枚举取值；
3. **索引策略**：哪些列建索引、单列/复合索引顺序、唯一索引；说明每条索引服务的查询；
4. **迁移策略**：如何在不停机/可回滚前提下变更（扩展-迁移-收缩、默认值回填、兼容旧数据）；
5. **查询模式**：预期读写路径，说明 schema 如何支撑它们（先有查询再定索引，避免过度设计）；
6. **数据访问层接口**：Repository / DAO 的方法签名与职责边界。

无数据库（`--no-db`）时：写明数据来源（外部 API / 文件 / 内存）与数据模型，仍产出本文件。

## 2. 全栈架构设计（03-architecture.md）

### 后端
- **接口设计**：端点/resolver 清单、请求与响应 schema、错误响应与状态码、版本策略；
- **服务层**：业务逻辑组件划分、各自职责与边界（控制器不写业务、服务不直接碰 HTTP）；
- **鉴权授权**：新接口如何接入现有认证体系、权限粒度；
- **集成点**：与现有服务/第三方系统的交互、超时与失败处理。

### 前端
- **组件层级**：页面组件 / 容器组件 / 展示组件的划分；
- **状态管理**：状态放哪、数据如何流动、哪些是服务端状态哪些是本地状态；
- **路由**：新路由、导航结构、路由守卫与权限控制；
- **接口对接**：取数策略、缓存、乐观更新、请求竞态与重试。

### 横切关注点
- **错误传递链**：后端异常 → API 错误响应 → 前端错误态，全链路闭环；
- **安全考虑**：输入校验、XSS、CSRF、越权、敏感数据；
- **风险评估**：列出技术风险点与缓解方案（集成不确定、性能热点、兼容性）。
