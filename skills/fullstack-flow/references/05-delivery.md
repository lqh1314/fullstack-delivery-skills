# Phase 5：部署交付与文档（产出 08、09 文件）

> 开工前读 03-architecture 与 07-testing。交付不是“代码写完”，而是可上线、可回滚、可交接。

## 1. 部署与基础设施（08-deployment.md）

- [ ] **CI/CD 流水线**：安装依赖、类型检查/lint、测试、构建、部署的阶段配置；测试不过禁止部署；
- [ ] **迁移上流水线**：数据库迁移作为部署的独立阶段，先迁移后发布应用；
- [ ] **灰度手段**（复杂功能）：特性开关，支持不发版关闭新功能；
- [ ] **健康检查**：新服务/接口的 liveness / readiness 探针；
- [ ] **监控告警**：错误率、延迟、吞吐等核心指标与阈值；
- [ ] **部署 runbook**：发布步骤、验证清单、**回滚步骤（含数据库回滚顺序：先应用后数据，或按迁移设计的收缩步骤）**；
- [ ] 全部沿用项目现有部署方式（Docker / Serverless / 主机 / 平台托管），不擅自换体系。

## 2. 文档与交接（09-documentation.md）

- [ ] **接口文档**：每个新端点的请求参数、响应示例、错误码；
- [ ] **数据库变更说明**：改了什么、迁移与回滚怎么跑、对存量数据的影响；
- [ ] **ADR（架构决策记录）**：关键选型的背景、考虑过的方案、为什么这么定；
- [ ] **用户文档**（如适用）；
- [ ] **交接摘要**：做了什么、如何在本地/测试环境验证、已知限制与后续 backlog。

### ADR 简模板
```markdown
# ADR-<编号>：<决策标题>
## 背景　## 候选方案与取舍　## 决定　## 后果与风险
```

## 3. 完成前真实验证（verification-before-completion）

按顺序实际执行，不能用“应该可以”替代：

1. 干净环境安装依赖 → 类型检查 / lint / 构建通过；
2. 完整测试套件实际跑一遍并全绿，记录结果；
3. 迁移正向 + 回滚各演练一次；
4. 启动真实服务/应用，按验收标准（01 中的勾选条目）逐条走主流程；
5. 对照 07 确认 Critical/High 清零；
6. 检查没有调试残留（console/print、硬编码密钥、注释掉的代码块）。

任一项失败：回到对应阶段修复后重跑全部验证（改了生成逻辑就要全量复验，不能只验改动点）。

## 4. 收尾

- state.json 置 `status=complete`、记录 last_updated；
- 最终总结固定包含：
  - 九个产出文件清单（`.fullstack-flow/`）；
  - 实现摘要（DB / 后端 / 前端各做了什么）；
  - 验证方式与结果（测试数、覆盖率、构建、手动验收）；
  - 已知限制；
  - 下一步建议（开 PR、按 runbook 部署、灰度观察）。
