# Phase 4：全流程验证（产出 07-testing.md）

> 开工前读 04/05/06 实现摘要。测试、安全、性能三个视角**并行推进、互不替代**；这是“会全流程测试”的核心阶段。

## A. 测试套件（QA / TDD 视角）

### 测试金字塔与覆盖要求
- **单元测试**：所有新增业务函数/方法，隔离外部依赖；
- **集成测试**：每个接口的成功、鉴权失败、参数非法、依赖异常路径；
- **数据层测试**：迁移可正向执行、回滚有效、关键查询结果正确；
- **组件/E2E 测试**：前端关键交互与主用户流程（如适用）；
- 每个功能至少覆盖三类用例：**正常路径 / 边界条件 / 错误处理**。
- 新代码覆盖率目标 **80%+**，核心业务逻辑分支全覆盖；覆盖率只是下限，断言质量比数字重要。

### TDD 纪律（复杂逻辑优先）
红（先写失败测试表达需求）→ 绿（最小实现让测试过）→ 重构（测试保护下改善结构）。禁止“先写一堆实现最后补测试”——补出来的测试倾向于复述实现而非验证行为。

### 框架探测（沿用项目现有栈，不新引框架）
Python: pytest / unittest；JS/TS: Jest / Vitest / Playwright / testing-library；Java: JUnit；Go: go test；.NET: NUnit/xUnit。项目没有测试框架时，先与用户确认再引入最贴合其栈的一个。

## B. 安全审计（安全视角，逐条给位置+严重度+修法）

- [ ] 鉴权：未登录/低权限能否访问新接口（水平/垂直越权）；
- [ ] 注入：SQL/NoSQL 注入、命令注入、模板注入（参数化查询、ORM 绑定）；
- [ ] XSS / CSRF：用户输入转义、输出编码、CSRF token / SameSite；
- [ ] 输入校验：类型、长度、范围、白名单，文件上传类型与大小；
- [ ] 敏感数据：日志/响应/错误信息中是否泄露密钥、内部信息；
- [ ] 依赖漏洞：新增依赖是否有已知 CVE；
- [ ] 安全反模式：硬编码凭据、前端存敏感信息、弱随机数。

## C. 性能审计（性能视角）

- [ ] N+1 查询、循环内查库；
- [ ] 缺失索引、全表扫描、深分页；
- [ ] 可缓存未缓存（热点读、字典数据）；
- [ ] 大 payload、未分页列表、不必要字段；
- [ ] 前端：不必要的重渲染、缺 memo/分页、大依赖进主包、未懒加载；
- [ ] 每条发现给出影响估计与具体优化建议。

## 严重度与处置规则

| 级别 | 定义 | 处置 |
|---|---|---|
| Critical | 可被直接利用的安全洞 / 主流程不可用 / 数据损坏 | 立即修复并复验，否则不交付 |
| High | 重要路径缺陷、明显越权、严重性能问题 | 本阶段内修复并复验 |
| Medium | 有触发条件的问题、体验缺陷 | 记录，与用户确认是否本次处理 |
| Low | 建议级优化 | 写入交接文档 backlog |

**回归规则（gstack QA 法）**：每修一个 bug，先写一个能复现它的失败测试，修复让测试转绿，该测试作为回归用例永久保留；修复后实机/真实接口再走一遍原路径确认。
